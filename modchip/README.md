# Local CPU LLM & Agentic Coding Container (`llama-modchip` + `Pi` + `OpenCode`)

## Overview
This container packages **[llama-modchip](https://github.com/synchopate/llama-modchip)** (a CPU-optimized fork of `llama.cpp` built for running large sparse Mixture-of-Experts models in system RAM) alongside the **[Pi](https://pi.dev/)** and **[OpenCode](https://opencode.ai/)** open-source terminal AI coding agents.

It allows you to run local quantized LLMs and agentic coding workflows without a discrete GPU and without running processes as `root`.

## Build

### Using Local `llama-modchip` Source vs. Git Clone
- **Local Source:** Place your existing `llama-modchip` repository directory at `./llama-modchip` alongside the `Dockerfile` before building. The build will copy it directly into the image.
- **Fallback:** If `./llama-modchip` is absent or empty, the build automatically clones the latest `main` branch from GitHub.

```sh
podman build \
  -v "$(pwd)/llama-modchip:/opt/llama-modchip" \
  -t modchip .
```

### Matching Your Host UID/GID (Optional)
The container runs as the non-root user `llm` (`UID 1000`, `GID 1000`).
If your host Linux user has a different UID/GID, pass them at build time so output files written to mounted volumes have matching ownership:

```sh
podman build \
  --build-arg USER_UID=$(id -u) \
  --build-arg USER_GID=$(id -g) \
  -v "$(pwd)/llama-modchip:/opt/llama-modchip" \
  -t modchip .
```

## Run

To keep model weights out of the container image and persist code/files generated by the LLM, bind-mount host directories when starting the container:

- **Project / Working Files:** `-v /path/to/host/workspace:/workspace`
- TCP Ports:
  - llama-modchip web gateway: 8787
  - OpenCode web UI: 4096

```sh
podman run -it --rm \
  --name modchip-dev \
  --userns=keep-id:uid=1000,gid=1000 \
  --ulimit memlock=-1 \
  -v "${HOME}/llm-workspace:/workspace" \
  -v "$(pwd)/llama-modchip:/opt/llama-modchip" \
  -p 127.0.0.1:8787:8787 \
  -p 127.0.0.1:4096:4096 \
  modchip
```

## Usage Instructions

### 1. Start the Local `llama-modchip` Inference Server

Inside the container shell, select and install an LLM:

```sh
/opt/llama-modchip/install.sh --workspace /workspace
```

- Select a suitable model for your computer
  - Hit Enter to accept recommendation based on your system
- Select the desired engine installation mode
  - Hit Enter to accept recommendation (download binary versus compile)
- Run `GATEWAY_HOST=0.0.0.0 /opt/llama-modchip/modchip start` to start the CPU server and web gateway in the background, accessible on the podman host in the browser at http://127.0.0.1:8787/
- Verify the server is ready: `curl -si http://127.0.0.1:8787/ | head`
- Optional: Run `/opt/llama-modchip/modchip status` to review the status of the LLM installation
- Optional: Run `/opt/llama-modchip/modchip chat` to start an interactive chat
- Optional: Run `/opt/llama-modchip/modchip bench` to benchmark your system, determining tokens/second for different scenarios
- Optional: Run `/opt/llama-modchip/modchip stop` to stop the background server and gateway

### 2. Access Pi
Once the server is running, start Pi inside `/workspace` (your mounted input/output project directory):

```sh
pi
```

- Inside the TUI, type `/model` and press **Enter** to confirm your model.
- Any files Pi reads or creates in `/workspace` will immediately appear in your mounted host folder (`~/llm-workspace/`).

### 3. Access OpenCode
Once the server is running, start OpenCode inside `/workspace`:

```sh
opencode
```

- Inside the TUI, type `/models` and press **Enter** to confirm your model or choose a different one.

#### Optional: Web UI Access
OpenCode also supports a browser-based interface.
Because port `8787` is used by the llama-modchip gateway, you can expose a different port (e.g., `-p 4096:4096`) when running the container and launch:
```sh
opencode serve --hostname 0.0.0.0 --port 4096
```
Access the OpenCode web UI in a browser on the host at http://127.0.0.1:4096/.

### 4. Get Another Shell
To get another shell inside the container, run:

```sh
podman exec -it --user llm modchip-dev bash
```

## Hardware & Performance Notes
- **BIOS iGPU VRAM:** Set UMA Frame Buffer Size to a low value, such as **512 MB to 1 GB**, in BIOS so the CPU has more system RAM available for model weights and context cache.
- **Physical Cores Only:** Keep thread count at `-t n` for `n` phyiscal cores. Even if the CPU has more threads than cores, using all threads typically reduces token generation speed on memory-bandwidth-bound systems.
- **Memory Locking (`--mlock`):** Prevents the Linux kernel from swapping to disk. Requires `--ulimit memlock=-1` on `podman run`.
